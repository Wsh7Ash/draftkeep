# Project spec — draftkeep

## Name

draftkeep

## Category

browser-extension

## Target user

Anyone who types a long answer into a web form and loses it by closing the tab, reloading, or navigating away. No developer tools needed after installation.

## Problem

Browsers restore form values only for back/forward navigation, and many SPAs discard them on reload. Users retype support tickets, checkout notes and applications. Existing form-saver extensions are often all-or-nothing and do not filter passwords or payment fields.

## Solution

A Manifest V3 extension that captures text fields per page into local storage, filters secrets before storing, expires old drafts and restores only into empty fields from a one-click popup.

## Core workflow

1. Install unpacked from the repository.
2. Type in a form.
3. Close or reload the tab.
4. Open the page, click the icon, click Restore.

## Must-have features

- debounced capture plus flush on hide/unload;
- per-page keying by origin + path;
- privacy filter for passwords, OTP and payment fields, enforced in the worker;
- merge with previous draft so disappearing fields keep their last value;
- restore only empty fields, matched by name/id, with framework-friendly value setting;
- 7-day TTL and 40-draft cap;
- popup list with Restore / Copy / Open / Delete / Clear;
- badge count;
- no network, no remote code, minimal permissions.

## Nice-to-have features

- per-site allowlist;
- encrypted storage;
- icons and store packaging;
- dirty-form close warning.

## Stack

Manifest V3, vanilla ES modules for the service worker and popup, one classic content script, `node --test` for the pure logic and manifest checks. No build step, no dependencies.

## Test strategy

- `tests/drafts.test.js` (20 tests): URL keying, sensitive-field detection, value normalization, sanitization caps and dedupe, merge semantics, draft building, validity guards, TTL/cap pruning, restore planning, age formatting, list summaries without values.
- `tests/manifest.test.js` (9 tests): Manifest V3 shape, module worker, referenced files exist, minimal permissions, http/https-only content script, version consistency, worker handles every message, content script never touches storage or `innerHTML`, popup has no inline script, no remote URLs/`eval`/`new Function` in sources.
- Manual browser procedure with `examples/test-form.html` for the DOM layer.

## Demo/result strategy

`results/sample-draft.json` is generated by calling `buildDraft` with a form that includes card and password fields; the output demonstrates that they are absent. `results/validation.log` captures the test run.

## Safety considerations

- Passwords, OTPs and payment fields are excluded by type, autocomplete and name/id patterns, in the worker rather than the page.
- Storage is local and unencrypted; documented as unsuitable for highly sensitive text.
- Minimal permissions (`storage`, `activeTab`), no host permissions, no remote code, no telemetry.

## Definition of done

- 29 tests green;
- manifest references only existing files;
- sample draft demonstrates the privacy filter;
- README covers installation, usage, limits and privacy;
- committed and published.
